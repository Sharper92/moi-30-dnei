# Мои 30 дней — путь к себе

Обновлённый проект для продолжения разработки в Codex. Это статическое веб-приложение на HTML, CSS и JavaScript: трекер привычек на 30 дней с деревом прогресса, календарём, наградами и резервным копированием данных.

Снимок опубликованной версии от **20 октября 2026 года**.

- Сайт: https://moi-30-dnei.palemoon8.chatgpt.site/
- Коммит исходников: `bc17bddbae3ad7e7bff62011f11e551d01410d49`.
- Версия данных: `4`.
- Исходники приложения и тесты в архиве совпадают с этим коммитом. Этот README добавлен при подготовке архива.

## Быстрый запуск

Распакуйте архив и откройте папку `moi-30-dnei` как проект в Codex. Из этой папки запустите:

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
```

Откройте http://127.0.0.1:8000/ в браузере. Для остановки сервера нажмите `Ctrl+C` в терминале.

Сборка, установка npm-пакетов, API-ключи и сервер приложения не требуются. Можно использовать другой статический HTTP-сервер, указав `dist` корнем сайта. `dist` здесь содержит редактируемые исходники, а не результат сборки.

В текущем коде service worker регистрируется только по HTTPS. При локальном запуске по HTTP можно работать с интерфейсом и сохранять отметки; для проверки установки PWA и офлайн-режима требуется HTTPS.

## Что изменено

Во вкладке «Привычки» у каждой текущей привычки есть два отдельных действия:

- **«Изменить»** — отредактировать текущую привычку.
- **«Заменить»** — выбрать другую привычку из каталога или создать свою, указав название, категорию, значок и дни выполнения.

При замене прежняя привычка сохраняется как отдельная версия со своими отметками. Новая получает собственный идентификатор и начинает собственную статистику. Накопленный опыт сохраняется; при просмотре прошлых дат отображается действовавшая тогда привычка. Завершённые версии доступны в разделе «История замен».

Если у прежней привычки сегодня есть отметка «Выполнено» или «Маленький шаг», замена начинает действовать завтра. Если сегодняшней отметки нет, замена действует с сегодняшней даты. Повторная замена ещё не начавшейся привычки сохраняет отложенную дату начала.

Ранее внесённые отметки, которые после замены оказались вне действующего расписания, показываются отдельно в блоке «Ранее отмечено».

Также обновлены кеширование PWA и загрузка новых файлов, добавлена миграция сохранений v3 → v4 и тесты замены привычек.

## Перенос личного прогресса

Прогресс хранится в `localStorage` браузера. Архив проекта содержит код; личные отметки, заметки и настройки переносятся отдельной JSON-копией.

1. На текущем сайте откройте **«Награды» → «Мои данные» → «Сохранить копию»**.
2. Сохраните полученный JSON-файл.
3. Откройте запущенный локально проект или новый адрес сайта.
4. Выберите **«Награды» → «Мои данные» → «Восстановить»**, укажите JSON-файл и подтвердите замену данных в этом экземпляре приложения.

Каждый адрес сайта имеет своё хранилище. Например, опубликованный сайт и `http://127.0.0.1:8000` используют разные данные. Сохраняйте один и тот же адрес и порт при локальной работе либо переносите данные через резервную копию.

### Формат данных

- Текущий ключ: `my30days-journey-v4`.
- Старый ключ: `my30days-journey-v3`.
- При отсутствии v4 приложение пытается прочитать и преобразовать v3. Старый ключ остаётся доступен.
- Импорт принимает поддерживаемые сохранения v3 и v4.
- `state.habits` содержит текущие и исторические версии привычек.
- У каждой версии есть уникальный `id`, номер позиции `slot`, `startDate` и `endDate`.
- `startDate` включается в период действия; `endDate` не включается. `endDate: null` обозначает последнюю версию позиции, которая может начинаться в будущем.
- Отметки в `state.entries[дата].statuses` привязаны к `id` версии привычки. Переносить старые отметки на новый `id` при замене нельзя: это изменит историю.

В приложении 19 позиций привычек. Замена сохраняет количество позиций, при этом число исторических версий может расти.

## Как растёт дерево

Дерево зависит от числа активных дат в 30-дневном периоде. Дата считается активной, если за неё есть хотя бы одна отметка «Выполнено» или «Маленький шаг». Количество XP не определяет стадию дерева.

| Активные дни | Стадия |
| --- | --- |
| 0 | Семечко. |
| 1–2 | Маленький росток. |
| 3–6 | Подросший росток. |
| 7–13 | Молодое дерево. |
| 14–20 | Дерево с большой кроной. |
| 21–29 | Цветущее дерево. |
| 30 | Цветущее дерево с золотистыми искрами. |

Дерево рисуется функциями `treeStage()` и `treeSvg()` в `dist/index.html`. Пропуск дня сам по себе не уменьшает накопленное число активных дней.

## Проверка

Для тестов нужен Node.js с модулем `node:test` (Node.js 18 или новее). Сторонних тестовых зависимостей нет.

Из корня проекта:

```bash
node tests/habit-model.test.cjs
```

Тесты проверяют миграцию v3, сохранность отметок, отдельную историю новой привычки, интервалы действия версий, начало замены сегодня или завтра, повторную отложенную замену, импорт/экспорт v4, ошибочные данные и неизменность исходного состояния при неудачной операции.

При подготовке опубликованной версии все 11 тестов прошли. Также проверены синтаксис JavaScript и наличие локальных ресурсов. Полная проверка интерфейса в браузере, установки PWA и обновления установленного приложения не проводилась.

## Контекст для дальнейшей разработки

Приложение работает без фреймворка, сервера и синхронизации между устройствами. Бизнес-логика распределена между основной страницей и двумя небольшими JavaScript-модулями; переписывать проект на другой стек для запуска не требуется.

Учтите текущие особенности при следующих изменениях:

- Календарь позволяет отмечать будущие дни. Активные дни дерева и XP учитывают весь 30-дневный период, а основной процент выполнения рассчитывается до текущей даты. Это может давать разные на вид показатели.
- Обычное редактирование расписания меняет дни недели у той же версии привычки и может пересчитать её прошлую статистику. Замена создаёт отдельную версию и сохраняет прежнюю отдельно.
- Предусмотрен один 30-дневный период; отдельного сценария архивации периода и начала следующего пока нет.
- Можно редактировать и заменять 19 привычек. Произвольное добавление и удаление позиций пока не реализовано.
- Даты вычисляются по локальному времени браузера.
- При обновлении файлов приложения на HTTPS-хостинге нужно учитывать service worker и менять версию кеша в `dist/sw.js`.

Для размещения на другом статическом хостинге укажите каталог `dist` в качестве публикуемого каталога. Пользовательские данные при смене адреса переносятся по инструкции выше.
