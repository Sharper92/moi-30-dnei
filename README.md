# Мои 30 дней — путь к себе

Многопользовательский трекер привычек на 30 дней. Интерфейс остаётся лёгким PWA на HTML, CSS и JavaScript. Проект поддерживает два варианта серверной части: Node.js + PostgreSQL для VPS и PHP 8 + MySQL для обычного виртуального хостинга.

## Возможности

- регистрация и вход по придуманному пользователем логину и паролю;
- защищённые серверные сессии в `HttpOnly` cookie;
- отдельный прогресс каждого пользователя;
- пустой список привычек у новых пользователей;
- добавление, редактирование и замена привычек с сохранением истории;
- обязательная смена временного пароля для начальных аккаунтов;
- первый начальный аккаунт имеет роль `admin`;
- пользователь Лия получает исходный набор из 19 привычек;
- автоматический перенос старого браузерного прогресса в аккаунт Лии при первом входе на том же домене;
- локальный кеш при временной потере связи и синхронизация с сервером;
- резервное копирование и восстановление JSON;
- PWA и офлайн-кеш интерфейса.

## Исправление счётчиков

XP, активные дни, полные выполнения и маленькие шаги теперь используют один период: от начала трекера до сегодняшней даты. Будущие даты можно просматривать, но нельзя отмечать заранее. Существующие будущие отметки сохраняются и начнут учитываться при наступлении соответствующей даты.

## Запуск через Docker

Требуются Docker и Docker Compose.

1. Скопируйте `.env.example` в `.env`.
2. Замените все временные пароли длинными случайными значениями.
3. Запустите:

```bash
docker compose up -d --build
```

Приложение откроется на `http://127.0.0.1:8080` или на порту из `PORT`.

Проверка состояния:

```bash
docker compose ps
docker compose logs -f app
```

Остановка:

```bash
docker compose down
```

Данные PostgreSQL сохраняются в Docker volume `postgres_data`. Команда `docker compose down -v` удаляет базу и не должна применяться на рабочем сервере без резервной копии.

## Начальные аккаунты

При первом запуске на пустой базе аккаунты создаются в строгом порядке:

1. администратор из `ADMIN_USERNAME` / `ADMIN_PASSWORD`;
2. Лия из `LIA_USERNAME` / `LIA_TEMP_PASSWORD`.

Оба аккаунта обязаны заменить начальный пароль после первого входа. Значения берутся только из `.env`; секреты не хранятся в Git.

Если таблица пользователей уже не пуста, повторный запуск контейнера не создаёт аккаунты повторно и не меняет их пароли.

## Хранение и безопасность

- Пароли хешируются `bcrypt` с cost 12.
- Сессионный токен состоит из 32 случайных байт; в БД хранится только SHA-256 хеш токена.
- Cookie имеет `HttpOnly`, `SameSite=Lax`, а в production также `Secure`.
- Вход и смена пароля ограничены по частоте запросов.
- Пользователь получает только собственное состояние; `user_id` берётся из серверной сессии, а не из запроса браузера.
- Состояние проверяется моделью приложения перед записью в БД.
- Обновления используют номер ревизии, чтобы обнаруживать одновременное редактирование с разных устройств.
- Заголовки безопасности задаются через Helmet.

Для production обязателен HTTPS на обратном прокси, например Nginx или Caddy.

## Структура данных

- `users` — логин, хеш пароля, роль и флаг обязательной смены пароля;
- `sessions` — серверные сессии с датой истечения;
- `user_states` — состояние трекера пользователя в JSONB и номер ревизии.

JSONB выбран осознанно: текущая модель трекера уже представляет единый небольшой документ, а такой формат позволяет добавить многопользовательский режим без переписывания всей бизнес-логики. Если позже появятся общие группы, социальные функции или сложная аналитика, данные можно нормализовать в отдельные таблицы.

## Разработка и тесты

Локально без контейнера нужен Node.js 20+ и доступный PostgreSQL:

```bash
npm install
npm test
npm start
```

Автоматические тесты проверяют миграцию старых данных, замену и добавление привычек, пустой старт нового пользователя и единый расчёт счётчиков без будущих отметок.

Сквозная проверка запущенного Docker-стека:

```bash
docker compose exec -T app node server/smoke-test.js
```

Она проверяет порядок начальных аккаунтов, 19 привычек Лии, пустой старт нового пользователя и сохранение первой привычки. Временный тестовый аккаунт удаляется автоматически.

## Обычный виртуальный хостинг PHP + MySQL

Вариант для хостинга без Docker находится в `shared-hosting/`.

1. Скопируйте файлы из `dist/` в корень сайта, переименовав `index.html` в `app.html`.
2. Скопируйте `shared-hosting/index.php` и `shared-hosting/.htaccess` в корень сайта, а `shared-hosting/api/` — в каталог `api/`.
3. Разместите конфигурацию по образцу `shared-hosting/config.example.php` на три уровня выше `api/index.php`, вне публичного каталога, под именем `moi30-config.php`.
4. Убедитесь, что активны PHP 8.1+ и расширения PDO MySQL, JSON и mbstring.
5. Откройте `/api/health`: API сам создаст таблицы с префиксом `moi30_` и два начальных аккаунта на пустой базе.

Для Web Push разместите содержимое `shared-hosting/push/` в каталоге `moi30-push` рядом с `moi30-config.php`, выполните там `php83 composer.phar install --no-dev --optimize-autoloader`, создайте закрытый `moi30-push-config.php` по образцу и запускайте `worker.php` раз в час через CRON. Администратор может управлять частотой автоматических сообщений и отправлять ручной Push из отдельного раздела приложения.

Сквозную проверку опубликованного варианта выполняет `shared-hosting/smoke-test.cjs`. Она проверяет вход администратора и Лии, обязательную смену временного пароля, регистрацию, пустой список нового пользователя, добавление привычки, смену пароля и повторный вход.

Файл с секретами не должен попадать в Git или быть доступен по HTTP. Пароли начальных аккаунтов используются только при создании пустой базы; дальнейшие запуски их не меняют.

## Основные файлы

| Файл | Назначение |
| --- | --- |
| `server/index.js` | API авторизации, сессий и состояния пользователя. |
| `server/schema.sql` | Таблицы PostgreSQL и индексы. |
| `server/db.js` | Миграция схемы и создание первых аккаунтов. |
| `dist/index.html` | Интерфейс входа и трекера. |
| `dist/habit-model.js` | Модель привычек, миграции, добавление и замена. |
| `dist/habit-stats.js` | Единый расчёт статистики и XP. |
| `dist/api.js` | Связь браузера с серверным API. |
| `dist/admin.js` | Панель пользователей, метрики активности и управление Push для администратора. |
| `docker-compose.yml` | Приложение и PostgreSQL. |
| `shared-hosting/api/index.php` | Самодостаточный PHP API для MySQL-хостинга. |
| `shared-hosting/.htaccess` | Маршрутизация API и заголовки безопасности Apache. |
| `shared-hosting/push/worker.php` | Почасовой планировщик автоматических Push-напоминаний. |
| `shared-hosting/push/send.php` | Отправка ручного Push из панели администратора. |
